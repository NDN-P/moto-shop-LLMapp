# Project proposal

I extended an existing motorcycle parts management application with a read-only natural-language catalog assistant for shop staff, retaining the React interface, SQLite workflows and local login. In shop mode it reads the owner's real inventory database without writes and sends the question plus selected product IDs, names, SKUs, categories, prices, stock quantities and minimum stock thresholds, or computed inventory totals, to the approved course proxy at `https://llm.nat-d.uk/v1`; descriptions, supplier details, photos and stock history are excluded. An explicitly marked invented catalog served as the development set and an optional sample mode. Python uses the OpenAI client and the required `gemma-4-E4B-it` model. Native function calls expose validated search, product lookup, low-stock lookup and inventory totals, and answers include checked source IDs and a visible trace, with bounded execution and a fallback when validation fails. I built the bilingual retriever on the invented catalog, froze it, and compared it with the shop's original name/SKU substring search and BM25 on 30 new hand-labelled questions over the real catalog (10 development, 20 held-out test), then ran a seven-question live check on the real database. Success is assessed through these reproducible measurements and honest reporting of failures (such as "cheapest engine oil"), the SKU data still sent to the proxy, and the absence of fitment data; they measure retrieval on one small shop, not general answer accuracy.
